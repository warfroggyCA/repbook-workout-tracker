# Contributing

Contributions are welcome when they preserve the tracker’s conservative data
and decision boundaries.

Use synthetic accounts, programs, exercises, workouts, timestamps, screenshots,
and database contents in every issue and pull request. Do not paste production
logs, private deployment details, real health or workout observations,
credentials, tokens, or owner-identifying information.

Before opening a pull request:

1. Read `AGENTS.md` and the documents it requires.
2. Add or update focused tests for the behavior.
3. Run the applicable verification in `docs/DEVELOPMENT.md`.
4. Explain user-visible behavior, data implications, verification, and any
   remaining limitation.

For a security concern, do not open a public issue. Follow `SECURITY.md`.
